# OpenCode Mobile 0.1.0-debug — что это и как смотреть

Неофициальный Android-клиент OpenCode (не продукт команды OpenCode).
Пакет: `ru.dredd20.opencode`. Подпись: **debug**. В репозитории и магазин не публиковалось.

## Что умеет этот билд

- Экран первого запуска (ru/en по языку системы) с дисклеймером, кнопка «Установить», ошибка/повтор.
- Встроенный runtime: PRoot (arm64-v8a и x86_64) + загрузка Ubuntu 24.04 (resume, sha256) + официальный OpenCode 2.3.0 linux-arm64/x64 (glibc, sha256) + apt (git, ripgrep, python3) + конфиг без автообновления и file watcher, изолированные HOME/XDG_*/TMPDIR.
- На armv7 приложение ставится, но встроенный сервер недоступен; предлагается удалённый режим.
- Режимы: встроенный (по умолчанию), Termux (RUN_COMMAND, динамический порт/пароль), удалённый сервер (URL + логин/пароль).
- `opencode serve` слушает свободный порт на 127.0.0.1 (не 4096), случайный Basic-пароль через `OPENCODE_PASSWORD`. Состояние пишется в приватный файл; живой сервер переиспользуется. Конфликт порта — повтор с другим. Пароль в JS не отдаётся, WebView отвечает на HTTP auth сам.
- WebView только на наш origin; внешние ссылки — в системный браузер. File chooser (SAF), загрузки, back, IME/adjustResize, тёмная тема, configChanges (поворот без пересоздания Activity/WebView).
- Планшеты: веб-UI десктопная вёрстка при ширине ≥ 768 CSS px (брейкпоинт packages/app). Нативные экраны — compact/medium/expanded, настройки в две панели на expanded.
- Свой Phone API (без GPL-кода Termux:API): unix-сокет (файловый на API 33+ через NIO, иначе abstract `ru.dredd20.opencode.phone`) + токен. CLI `termux-*` и `phone-mcp` (stdio, type local) ставятся в rootfs автоматически. Категории тумблеров; SMS/контакты выкл. по умолчанию; опасные действия с подтверждением в UI. Звонок только через ACTION_DIAL.
- USB OTG: список устройств, USB-serial (open/read/write/baud) через usb-serial-for-android (MIT). Передача сырого fd в proot (SCM_RIGHTS / `termux-usb -e`) **отложена на v0.2**.
- Браузер агента **не в v0.1** (следующий этап). webfetch сервера работает как есть.

## Известные ограничения

- Полный цикл «установка Ubuntu + serve + WebView UI + termux-battery-status + MCP» на эмуляторе в этой сборке **не прогонялся до конца** (долгая загрузка ~150+ МБ и apt). Логика порта/переиспользования и протокол Phone API покрыты юнит-тестами.
- Отдельный планшетный AVD не создан: пакет `google_apis_tablet` через sdkmanager в этой среде не установился. Скриншоты «планшета» сняты на AVD `murf-embed35` с геометрией Pixel Tablet (`wm size 2560x1600` / `1600x2560`, 276 dpi).
- Уведомление «ответ агента завершён» в v0.1 не сделано.
- Настройки в двух панелях на широком экране: переключатели выравниваются по правому краю левой колонки (можно улучшить в v0.2).

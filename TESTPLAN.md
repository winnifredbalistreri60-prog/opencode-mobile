# План проверки OpenCode Mobile 0.1.2-debug

APK: `opencode-mobile-0.1.2-debug.apk` (debug-подпись, тот же ключ что у 0.1.0/0.1.1,
SHA-256 сертификата `65b96eb0…2a90`). Ставить напрямую, не Play. Можно ставить
поверх 0.1.1 без удаления данных. Ключ в репозитории отсутствует: сборка читает
`debug.keystore` из `local.properties` или `OPENCODE_DEBUG_KEYSTORE`.

## На x86_64 эмуляторе / устройстве (Android 14/15)

AVD: `murf-embed35` (телефон, 1080×2400) и `oc-tablet35` (pixel_tablet, google_apis_tablet
API 35, 2560×1600). Одновременно два эмулятора на 16 ГиБ хоста раньше уходили в OOM —
гонять последовательно. После `emu kill` для пользователя `box` восстановить
`setfacl -m u:box:rw /dev/kvm`.

1. Обновление: 0.1.1 уже стоит → установить 0.1.2 с `-r` (не `-d`). Rootfs на месте,
   Start открывает официальный веб-UI без пароля. Подпись должна совпасть.
2. Чистая установка (uninstall + install) на одном из AVD: Setup → Install до
   «Ready: OpenCode 2.3.0» без `apt failed: code 100`. Retry не должен качать архивы
   заново, если sha256 уже совпадает (маркеры `.opencode-cli-version` / apt / config).
   По возможности: оборвать сеть во время download и во время apt, нажать Retry,
   убедиться, что завершённые шаги пропускаются, а недокачанный архив докачивается.
3. Start. FGS-уведомление с одним актуальным портом. Пароль не виден в `ps` argv.
   WebView 124: полифил и баннер про 126+.
4. 20 циклов Stop/Start подряд: без FATAL/`RejectedExecutionException` /
   «Address already in use», процесс жив, Phone API снова слушает сокет. Если порт
   свободен — тот же порт и те же cookie (нет «Can't reach this server»).
5. Чат: создать сессию (не строка поиска; закрыть промо «Control your browser»),
   отправить короткое сообщение на бесплатную `opencode/*` (например `big-pickle`).
   Дождаться ответа в UI. Уйти в фон во время (или перед концом) хода — должно
   прийти уведомление «Agent reply is ready» / «ответ агента готов».
   Если 429 — это квота сервиса; запасной вариант: OpenAI-совместимый mock на хосте
   `10.0.2.2`.
6. Настройки: первая системная Назад закрывает Settings, WebView сессии не
   перезагружается (введённый текст / вкладка на месте), если origin не менялся.
7. MCP: в госте `opencode --server http://127.0.0.1:$port mcp list` → `✓ phone connected`.
   `termux-torch off` должен выключить фонарик и вернуть JSON, не «включить».
   `termux-location` всегда JSON (в т.ч. `{"error":"permission_pending",...}`), не голая строка.
8. Режим Termux: без установленного Termux — инструкция про F-Droid/GitHub и
   `allow-external-apps=true`, не бесконечное Waiting. Start/Stop доступны.
   Если Termux установлен — полный цикл RUN_COMMAND.
9. Remote: неполный URL не должен превращаться в порт 80; статус не смешивается
   с embedded. Start открывает сессию. Живой LAN-сервер — по возможности.
10. Поворот / скрепка / внешние ссылки — регресс 0.1.1 (отмена SAF не роняет процесс).

## Планшет

Прогнать обновление или чистую установку, Start, веб-UI, Stop/Start (хотя бы несколько
циклов), Назад из Settings. Для двух колонок настроек — ширина ≥ 840 dp
(`wm density 276` на `oc-tablet35`, либо ориентация).

## Реальный arm64-телефон (обязательно для релиза)

То же, что выше, плюс скачивание `opencode-linux-arm64.tar.gz`, 16K page size,
Phone API на железе, USB OTG list, режим Termux и Remote в LAN. На armv7 —
только удалённый сервер и понятное сообщение.

## Не проверять как готовое

- Встроенный агентский браузер (намеренно не в v0.1).
- `termux-usb -e` / SCM_RIGHTS.
- Публикация / release-подпись.
- Квоты бесплатных моделей `opencode/*` как баг клиента.

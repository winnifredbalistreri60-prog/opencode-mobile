# План проверки OpenCode Mobile 0.1.0-debug

APK: `opencode-mobile-0.1.0-debug.apk` (debug-подпись). Ставить напрямую, не Play.

## На x86_64 эмуляторе / устройстве (Android 14/15)

1. Чистая установка APK. При первом запуске — экран Setup, дисклеймер «неофициальный клиент», кнопки Install / Remote.
2. Install: должен качать ubuntu-base 24.04 и `opencode-linux-x64.tar.gz` v2.3.0 с прогрессом, sha256, возможностью повтора (докачка). Нужно ≥ 2,5 ГБ свободно и интернет. Это занимает много времени и трафика.
3. После «Установка завершена» — Start. В уведомлении FGS должен быть порт (не обязательно 4096). WebView открывает веб-UI. Авторизация без ввода пароля. Проверьте в logcat, что пароль **не** печатается.
4. Из bash в rootfs (через любой debug-shell в proot, либо позже добавим кнопку): `termux-battery-status`, `termux-sensor -l`. В настройках OpenCode (веб-UI) MCP-сервер `phone` должен быть в списке.
5. Стоп — процесс proot и потомки убиваются (`ps` не показывает opencode serve). Повторный Start без ошибки порта. Если занять порт другим процессом — сервер выбирает другой.
6. Поворот телефона и split-screen: WebView не должен перезагружаться с нуля (Activity не пересоздаётся).
7. Внешняя ссылка из UI уходит в Chrome; выбор файла (скрепка) открывает SAF.

## Планшет

Интерфейс должен быть шире: настройки — две колонки (слева контролы, справа логи) при ширине ≥ 840 dp. Веб-UI OpenCode — десктопная вёрстка при ≥ 768 dp (на телефоне в ландшафте с шириной ≥ 768 тоже). Желательно прогнать на настоящем Pixel Tablet / AVD `pixel_tablet` API 35, если образ есть.

## Реальный arm64-телефон (обязательно для релиза)

1. То же, что п.1–7, но скачивается `opencode-linux-arm64.tar.gz` (sha256 `3207fb5cdec448d479242c0f1a14f4f7bdfcad3a79209b5eb8f9003725e93711`).
2. 16K page size (некоторые Pixel 8/9): бинарь формально с p_align=64K, но это нужно подтвердить запуском `--version` / serve.
3. Phone API: батарея, список сенсоров, toast, вибрация, фонарик, TTS, share, open-url. Геолокация и фото — с runtime-разрешением и (для фото) подтверждением. Звонок открывает системный набор, не звонит сам. SMS/контакты по умолчанию выключены; при включении — диалог подтверждения.
4. USB OTG: `termux-usb -l` (или tool `usb_list`) показывает устройство; serial open/read/write, если есть переходник. Передача raw fd в proot в этом билде **нет**.
5. Режим Termux (если установлен F-Droid Termux): разрешение RUN_COMMAND, `allow-external-apps=true`, запуск serve, тот же WebView.
6. Удалённый режим: URL компьютера с `opencode serve` + пароль.
7. На armv7 (если такое устройство есть): понятное сообщение и только удалённый сервер.

## Не проверять как готовое

- Встроенный агентский браузер (намеренно не в v0.1).
- `termux-usb -e` / SCM_RIGHTS.
- Публикация / release-подпись.

# План проверки OpenCode Mobile 0.1.1-debug

APK: `opencode-mobile-0.1.1-debug.apk` (debug-подпись, тот же ключ что у 0.1.0, SHA-256 сертификата `65b96eb0…2a90`). Ставить напрямую, не Play. Можно ставить поверх 0.1.0 без удаления данных.

## На x86_64 эмуляторе / устройстве (Android 14/15)

AVD для регрессии этой ветки: `murf-embed35` (телефон, 1080×2400) и `oc-tablet35` (pixel_tablet, google_apis_tablet API 35, 2560×1600). Одновременно два эмулятора на 16 ГиБ хоста раньше уходили в OOM — гонять последовательно. Для `oc-tablet35` пользователю `box` нужно rw на `/dev/kvm` (`setfacl -m u:box:rw /dev/kvm`); после пересоздания узла ACL может пропасть.

1. Чистая установка APK. Экран Setup, дисклеймер «неофициальный клиент», объём (~150 МБ сети, ~800 МБ диска), интернет, кнопки Install / Remote. На планшете Install не на всю ширину.
2. Install: ubuntu-base 24.04 и официальный `opencode-linux-x64.tar.gz` v2.3.0 с прогрессом и sha256. apt (git, ripgrep, python3) должен дойти до «Ready: OpenCode 2.3.0» **без** `apt failed: code 100`. Retry не должен заново качать CLI, если бинарь уже той же версии. UI сам переходит к Start, без ухода в настройки и назад.
3. Start. В уведомлении FGS — актуальный порт (одно значение, не два разных). WebView открывает официальный веб-UI **без** экрана pairing/пароля (нативный `/auth/connect/{code}`, HttpOnly cookie). Пароль **не** виден в `ps -A` / argv. На WebView 124 должен работать полифил и баннер про обновление до 126+; на слишком старом WebView — понятная ошибка, не белый экран.
4. Чат: создать сессию, отправить сообщение. Если бесплатные `opencode/*` доступны — дождаться ответа. Если 429 / нет провайдера — зафиксировать, это не регресс приложения. При уходе в фон во время ответа должно прийти уведомление «ответ агента готов» (SSE `session.idle` / `session.execution.succeeded`) — проверить, когда модель реально отвечает.
5. MCP: в госте `set -a; . /run/opencode-password; set +a; opencode --server http://127.0.0.1:$port mcp list` → `✓ phone  connected`. Вызов `battery_status` (или tool из UI) должен вернуть JSON, не timeout. Голый `opencode mcp list` без `--server` не считать источником истины.
6. Стоп: `serve-state.json` исчезает, proot/serve нет в `ps`. Повторный Start без FATAL (`RemoteServiceException` / отсутствие `startForeground`) и без ошибки порта. Если занять порт — берётся другой. Статус показывает один актуальный порт.
7. Поворот и split-screen: WebView не перезагружается с нуля (Activity не пересоздаётся).
8. Скрепка: открывается SAF, **отмена** (Назад) не роняет процесс; выбор файла, если в SAF есть видимый документ, тоже не роняет. Внешние ссылки — в системный браузер.
9. Настройки: на телефоне логи свёрнуты; системная Назад из App settings возвращает к сессии, а не закрывает приложение. Режимы — radio. Пароль Remote замаскирован. Start в Remote открывает сессию. Если Termux не установлен — сообщение, а не молчание. Update при запущенном сервере предлагает остановить и обновить.
10. Phone API: батарея, сенсоры, toast, вибрация, фонарик, TTS, share, open-url. Геолокация и фото — категория по умолчанию **выкл.**; при включении — runtime-разрешение (тап по уведомлению открывает системный диалог) и для фото подтверждение. Звонок — категория system, только ACTION_DIAL, не требует comms. SMS/контакты по умолчанию выкл.
11. Обновление: установить 0.1.0, затем 0.1.1 поверх (без `-d` при повышении versionCode). Данные rootfs сохраняются, serve и авто-вход работают. Подпись должна совпасть, иначе система потребует uninstall.

## Планшет

Интерфейс шире: настройки — две колонки (слева контролы, справа логи) при ширине ≥ 840 dp (у `oc-tablet35` при плотности 320 это 800 dp — для двух колонок поставить `wm density 276`, как у настоящего Pixel Tablet, либо поворот так, чтобы ширина ≥ 840 dp). Веб-UI OpenCode — десктопная вёрстка при ≥ 768 CSS px. Прогнать пункты 1–9 на `oc-tablet35`.

## Реальный arm64-телефон (обязательно для релиза)

1. То же, что п.1–11, но скачивается `opencode-linux-arm64.tar.gz` (sha256 `3207fb5cdec448d479242c0f1a14f4f7bdfcad3a79209b5eb8f9003725e93711`).
2. 16K page size (некоторые Pixel 8/9): подтвердить `--version` / serve.
3. Phone API как в п.10, на железе.
4. USB OTG: `termux-usb -l` / `usb_list`; serial open/read/write при наличии переходника. Передача raw fd в proot в этом билде **нет**.
5. Режим Termux (F-Droid Termux): RUN_COMMAND, `allow-external-apps=true`, запуск serve, тот же WebView без запроса пароля.
6. Удалённый режим: `http://` в LAN — предупреждение о cleartext, затем WebView без ручного pairing. `https://` без предупреждения.
7. На armv7: понятное сообщение и только удалённый сервер.

## Не проверять как готовое

- Встроенный агентский браузер (намеренно не в v0.1 / 0.1.1).
- `termux-usb -e` / SCM_RIGHTS.
- Публикация / release-подпись.
- Бесплатные лимиты `opencode/*` (это квота сервиса, не клиент).
